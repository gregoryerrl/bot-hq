## 1. Executive summary

**Nine things worth fixing first (all H, all verified at the line; "seam n" = row n of `CODEBASE.md` §14):**

1. **The D15 close-out learnings epilogue is inert** — `AppState::close_session`
   waits with `await_both_idle` immediately after `broadcast`, but since
   `519cbba` broadcast marks nobody busy, so the wait returns at once, the outcome
   is recorded as "Declined" and `teardown_session` kills the agents before the
   ring deals the turn. Live proof: `s-381a8b49` prompt row 07:35:43.763Z →
   "wrote nothing" 07:35:43.770Z (7 ms), 1 outcome row across 11 closes since
   08-14. `src/core/state.rs:757-765`. (B1-F6 / T-1)
2. **A holder that can never complete wedges the ring with nothing declared** —
   three triggers, one consequence, one fix: (a) closed stdin →
   `Stop::Unreachable` → `warn!` only (`src/core/sequencer.rs:2892-2896,2981-2999`);
   (b) pump `Exited` mid-turn mints no `TurnComplete`/`HaltDeclared`
   (`src/core/duo.rs:951-1003`); (c) a deal with an EMPTY backlog marks the holder
   busy before the empty-page check (`src/core/sequencer.rs:2287` vs `:2798`; both
   `start_turn` sites lack an unread precondition — traced, not yet observed
   live). In every case the holder stays set, the busy flag stays set, no halt
   slot is filled and no holder is cleared; the watchdog does fire
   `notify_agent_health` for a dead pump (`src/core/watchdog.rs:209-222`) but its
   idle nudge cannot cover a wedge that reads Busy (`:229`), so the only signal is
   the health dot. Fix at the ring: on unreachable/exit/empty, clear busy,
   `halt()`, fill the slot with the reason. (B1-F2, B1-F3, B1-F4; seam 9)
3. **Approval gates are detected by the literal option string
   `["Approve","Reject"]`** at four Rust sites + the FE, and the ring's
   `open_gates` is a bare counter — a plain question with those options sends a
   spurious `GateResolved`; and the gate LIFT (`notify_ring_gate(false)`) is
   UNPINNED: cut it and the ring deals nothing for the rest of the process after
   the first approval (EYES reproduced: `tray.rs:616` commented out → `cargo test
   --lib` 1131 passed, 0 failed). `src/signaling/bridge/tray.rs:604-613`,
   `src/core/sequencer.rs:1781-1783`, `src/core/state.rs:1594`,
   `src/storage/tray.rs:115`. (C2-2, B1-F16; seam 14)
4. **The internal MCP server has no caller authentication** — identity is the URL
   path (`/sessions/<id>/<slug>/mcp`); an EYES agent with Bash can POST to the
   `hands` URL and call any HANDS-only tool. The sibling external server does
   bearer + constant-time compare. `src/signaling/server.rs:152-166`. (C1-1)
5. **Every git-hook internal error is exit 0** — `run_cli(...).unwrap_or_else(|_| 0)`
   in `src/main.rs:674-678`; a malformed `policy.yaml` therefore bypasses
   `push_gate:ask` / `force_push:blocked` although `hooks.rs` documents pre-push
   as fail-closed. (E1)
6. **Six MCP tool descriptions (prompt text every agent reads) still assume a
   duo** ("the duo settles", "both agents", "either agent", "peer-forwarding");
   the D10 sweep test greps only "brian/rain". `src/signaling/protocol.rs:191,212,222,250,269,346`. (C1-2)
7. **`migrations/0056` was deleted after being applied on this machine** —
   sqlx `ignore_missing=false` ⇒ any DB that applied it fails to boot with
   `VersionMissing(56)` until `_sqlx_migrations` is hand-repaired (the dev DB was);
   no WAL either (`PRAGMA journal_mode` = delete with an 8-connection pool + an
   out-of-process hook reader). `src/storage/mod.rs:67-81`. (F2, F1)
8. **Frontend: the ApprovalGate command box is a bare `overflow-auto` `<pre>`**
   (horizontal scroll on the safety-critical surface, against the absolute
   rule) and **the CL editor discards unsaved edits** on tab switch/close/project
   removal with no confirm. `frontend/src/components/ApprovalGate.tsx:131`,
   `frontend/src/app/ContextLibrary.tsx:457-482`. (J1, L1)
9. **The canonical docs drifted from rc3 in load-bearing places** —
   ARCHITECTURE.md self-contradicts on model resolution (`brian_model_id` vs
   "all now unread"; code agrees with the latter), omits the 0044 tables, the
   halt slot, gates, Stage, BOOT, lists 36 tools (registry: 40); README/INSTALL
   still describe the deleted native loop as a selectable backend; the public
   site says "Two AI agents"; `CLAUDE.md`'s plugin paragraph is wrong on three
   counts; PLAN.md's In-flight list is mostly shipped; the CL trackers carry
   ~24 stale entries (T-1…T-24). (M-F1…F6, T)

**Also notable (M):** `unregister_session` leaks 6 of 16 bridge registries incl.
the ring `tx` (orphan ring task per closed session; a respawned session inherits
the old attention badge) (C2-1/B1-F5) · a halt can be shown/latched with no
